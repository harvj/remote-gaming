# Visual reviews

Save screenshots directly in a feature or release directory under `docs/design/`. Use descriptive filenames such as `directory-desktop.png`, `modern-art-tabletop-mobile.png`, and `navigation-scrolled.png`.

Include before and after screenshots when evaluating a change. Use the feature or release README to show the images with relative Markdown links and make each image individually openable. Record the source revision, viewport and capture environment, including whether the image came from a hosted deployment or a disposable fixture.

Commit the images and README with the implementation or in a dedicated review commit. Share GitHub links to both the review directory and its README. Create ZIP review packets only on explicit request.
